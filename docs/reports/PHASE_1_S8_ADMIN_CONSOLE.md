## 2. What was built

- **Migration `20261027120000_p1_s8_admin_console`** (forward-only): enum `admin_step_up_status`, table `app.admin_step_ups` (non-tenant, RLS forced, no application grant), a partial index for the platform audit view, seven invoker helpers owned by svc_definer and executable by no application role (`admin_session_valid`, `admin_step_up_until`, `admin_step_up_locked_until`, `admin_require`, `admin_audit`, `mask_email`, `admin_query_kind`), seven new definer functions for app_admin (`admin_console_state`, `admin_step_up_begin`, `admin_step_up_finish`, `admin_list_workspaces`, `admin_get_workspace`, `admin_list_users`, `admin_list_audit`), and `admin_set_workspace_status` replaced by a six-argument version (session id added; outbox rows per project). New svc_definer grants: step-up table, `identity.sessions (id, user_id, expires_at)`, `identity.users (created_at)`, four workspace columns, audit-log columns with policy `definer_select_platform` (platform and admin-written rows only), outbox INSERT of fresh `sites.hosts.changed.v1` rows only.
- **`@platform/db/admin`** (new subpath): `createAdminDatabase` (pg pool only; refuses any URL that is not app_admin; query timeout 5 s, connect timeout 10 s after S7-10; `verifyRole`). `@platform/db/testing` gained `createSessionRow`, `steppedUpAdmin`, `stepUp` fixtures.
- **`@platform/workspaces`**: `createAdminService` (input validation, the step-up sequence, error translation, paging, after-commit dispatch of the suspension's outbox rows); error codes `MFA_CODE_INVALID`, `MFA_LOCKED`.
- **`@platform/auth`**: `verifySessionTotp` (server-side `auth.api.verifyTOTP`); a `before` hook that refuses the HTTP verify endpoints for a session whose user already has 2FA (S8-1).
- **`apps/dashboard`**: `lib/admin.ts` (lazy app_admin runtime with role check; `adminContext` guard, 404 for non-admins; `requireAdmin` for step-up), `app/actions/admin.ts` (`adminStepUpAction`, `setWorkspaceStatusAction`), pages `/admin`, `/admin/step-up`, `/admin/workspaces`, `/admin/workspaces/[id]`, `/admin/users`, `/admin/audit` (all `noindex`, audited-actions banner). The workspace runtime exposes its outbox.
- **ESLint**: `@platform/db/admin` may be imported only by `packages/workspaces/src/admin.ts` (and its unit test), `packages/db` and `apps/dashboard/lib/admin.ts`; apps/sites may not import it (probed in all three places, probes removed).
- **`db:verify`**: 28 checks (was 24): eight admin definers in the list; app_admin executes exactly those eight; the helpers are executable by no application role; app_admin is denied the step-up table; a caller without a stepped-up session is refused (read-only probe).
- **Isolation suite**: `tests/isolation/src/admin.test.ts`; `app.admin_step_ups` classified as a non-tenant relation; both server actions registered (no selector: cross-workspace by design, authorization probed by the admin suite); mutations M10 and M11.
- **Dependencies:** none added. **New variable:** dashboard `DATABASE_URL_ADMIN` (already in `.env.example`; DG-21).

## 4. Security review

- **Authorization (SEC-17).** Four conditions, all in the database, on every call (D1). app_admin holds no privilege on any product relation (catalog-checked for every relation) and executes exactly the eight console functions; no tenant, auth or visitor role executes any admin function or helper. The owner of a workspace, with MFA and a live session, is refused by every console function and cannot start a step-up; a granted admin on a second, not stepped-up session is refused. Mutations M10 (step-up check removed) and M11 (app_user granted a console function) are killed.
- **Step-up.** TOTP verified by Better Auth (encrypted secret), recorded by the database; lockout 5 per 15 minutes including abandoned attempts; 8 parallel attempts yield exactly 5 (advisory lock). An attempt is finished once, only by its own admin and session, within 5 minutes.
- **Residual: the app_admin credential.** The database cannot check a TOTP code. A holder of `DATABASE_URL_ADMIN` who also knows a live admin session id could record a step-up without the code. Controls: the variable is a server-only secret of the dashboard project (like `DATABASE_URL`), session ids never reach browsers (the cookie carries the token), every step-up is audited with the admin's id. Accepted for P1; revisit with impersonation (P8).
- **Data minimisation and privacy.** D5/D6; tests assert that no name, client contact, project name, member address or searched text appears in answers or audit rows. The console adds no processor and no new personal-data store (step-up rows hold user and session ids and times). Privacy inventory: unchanged (no new processor).
- **Abuse.** Search length limits (100 / 254), LIKE wildcards escaped, page size ≤ 100, action filter validated in SQL and TypeScript, ids validated before any call. Server actions are POST-only Next actions with the dashboard's origin checks.
- **IDOR.** The console is cross-workspace by design, so the IDOR harness's "foreign id = missing id" property does not apply; the two actions are registered with that reason and their authorization is probed by the admin suite.
- **Sites (D12).** Suspension invalidates every project's cache entries in the same transaction's outbox; the sweep re-emits lost rows; the 300 s TTL bounds a total loss.
- **Better Auth (S8-1, S8-2).** Fixed and documented; both re-checked on upgrade.
- **Threat model:** five rows added (admin console, step-up, search, suspension, app_admin credential).
