## 2. What was built

- **Migration `20261024090000_p1_s6_projects_lifecycle`** (forward-only, additive except one revoked grant, D3):
  - `app.project_transition_roles(from, to)` (the transition table) and trigger `projects_guard`: invalid transition P5002, wrong role 42501, archived project read-only P5003, Live needs an active platform subdomain P5006; `created_by` and `status_changed_at` set by the database.
  - Projects and client contacts: INSERT/UPDATE policies need owner, admin or editor (viewers read only).
  - Domains: `REVOKE INSERT` from app_user (D3); `app.allocate_platform_subdomain(project, label)` (definer); CHECK `domains_subdomain_label_not_reserved`; domain soft-delete for owners/admins only.

  - `app.notification_preferences` (member-own writes), `app.notification_delivery(id)` (definer, job scope only: recipient address + choices).
  - `app.outbox_events` (ids-only payloads, fresh rows pinned by policy) and `app.outbox_pending(limit, min_age)` (definer, answers only with no context at all).
  - `app.job_dead_letters` (append-only for app_user, owner/admin read).
- **`@platform/db`**: `withSystem()` (no context, outbox sweep only; ESLint-confined), `db:configure`, `db:verify` checks the new definers and `sites_domain`.
- **`@platform/jobs`**: `notification.email.v1` (3 retries, idempotent on `notificationId`, 5 per workspace, dead-letter hook) and the cron `outbox.sweep.v1` (every 5 minutes, concurrency 1); emitter `notificationEmailRequested(ids, { eventId })`, the outbox id being the event id.

## 4. Security review

- **Authorization order.** As in S5: workspace id (selector) → membership (`resolveTenantScope`) → capability (`authorize` semantics; a transition's capability comes from the pure transition table, before any lookup) → project lookup → mutation + audit in one RLS transaction. Foreign and unknown ids give the same NOT_FOUND; refusals are audited `denied`.
- **Defence in depth (SEC-10).** Database repeats: transition table and roles (trigger), viewer cannot insert or update projects/contacts, no direct domain insert, allocator refuses foreign projects/viewers/job scope, members write only their own preferences, outbox rows cannot be inserted pre-dispatched.
- **IDOR.** Every new action (9), page loader (9) and the export route are registered and probed (isolation suite: 181 tests, was 122).
- **Privacy.** Client contact PII never in audit metadata or logs (asserted); dead-letter errors are redacted (asserted: an address in a provider error does not reach the row); Inngest payloads are ids only; audit viewer hides IP/UA. Privacy inventory: two rows added, Inngest row extended.
- **Abuse.** Project creation limit (D10); search input capped at 100 characters and LIKE wildcards escaped; CSV formula injection neutralised.
- **Residual.** Audit export by GET (D11). `outbox_pending` is executable by app_user but answers only with no context; an attacker with code execution in the app could read event ids across workspaces (ids only). Server actions still lack a per-IP limit (S9 review). Threat model: four rows added.

## 5. Schema, compatibility, migration and rollback

One forward-only migration; `schema.prisma` updated (`db:drift`: no difference). Revoked: app_user INSERT on `app.domains` (no application code used it; S1/S2 tests moved to the allocator or to `svc_definer`). Replaced policies: projects and client contacts (`tenant_*` → `editor_*`), domains update (`tenant_update` → `manager_update`). New columns on `projects` are nullable. **Before the live migration:** run `db:configure --target env` with an Owner-chosen `sites_domain` (DG-18), otherwise live project creation answers "addresses not set up" (fail-closed). Rollback before product data exists: reverse script (drop the new tables, functions, trigger, constraint and policies; restore the S1 policies and the domains INSERT grant); after data exists, forward fixes only. New environment variable for operators: `SITES_DOMAIN` (only for `db:configure --target env`). Inngest: the app now serves `notification.email.v1` and `outbox.sweep.v1`; a resync is needed when deployed (DG-17).
