## 2. What was built

- **Migration `20261023120000_p1_s5_workspaces_rbac`** (forward-only, additive):
  - `app.reserved_slugs()` / `app.is_reserved_slug()` and CHECK `workspaces_slug_not_reserved`.
  - `app.current_member_role()` (definer; avoids policy recursion) and `app.workspace_has_members()` (bootstrap of the creator's own owner row).
  - Memberships: INSERT/UPDATE need owner or admin, DELETE needs owner/admin or the member themself (leave). Trigger `memberships_guard`: only an owner may grant, change or remove the owner role; every owner-row change takes a per-workspace advisory lock. Deferred constraint trigger `memberships_keep_owner`: a workspace keeps at least one owner (SQLSTATE `P5001`), checked at commit so a transfer works in either order.
  - Workspaces: settings UPDATE needs owner/admin; trigger `workspaces_guard`: deletion request/cancel owner-only, dates set by the database.
  - Invitations: INSERT/UPDATE need owner/admin and `invited_by = actor`; expiry bounded to 30 days.
  - Definer functions for `app_user`: `accept_invitation(token_hash, correlation_id)` (actor from `app.user_id`, verified address must equal the invited one, row lock = accept-once, membership `ON CONFLICT DO NOTHING`, audit row, inviter notification), `invitation_preview(token_hash)` (workspace name, role, masked address), `workspace_members()` (names/addresses from `identity` for members of the current workspace only).
- **`@platform/db`**: `withJobTenant(workspaceId, fn)` (workspace context without an actor) for job handlers only; ESLint forbids it elsewhere.
- **`@platform/auth/rbac`**: capabilities, `can`/`authorize`, `ForbiddenError`, `assignableRoles`.
- **`@platform/jobs`** (was a placeholder): `loadJobsConfig` (ADR-007 rule 1 / G-1), ids-only event contract `workspace.invitation.created.v1`, the Inngest function (3 retries, idempotency on `invitationId`, concurrency 2 per workspace, `onFailure` dead letter), `/api/inngest` handlers, and an inline transport for local development and tests (refused when deployed). ESLint forbids importing `inngest` outside this package (rule 3 / G-4).
- **`@platform/workspaces`** (new package): reserved slugs and `slugify`, invitation tokens (token = HMAC-SHA256 of the invitation id under an HKDF-derived key from `BETTER_AUTH_SECRET`; only SHA-256 stored), the invitation mail, the workspace service (19 commands and queries) and the job handler with dead letter.
- **`apps/dashboard`**: `/` (pending invitation → remembered workspace → first workspace → onboarding), `/workspaces/new`, `/w/[slug]` (overview, projects placeholder, members, settings), `/invite/[token]`, header switcher, workspace-aware navigation, 14 server actions in `app/actions/workspaces.ts`, `/api/inngest`. `Referrer-Policy: no-referrer` and `Cache-Control: no-store` on `/invite/*`.
- **CI** (`db-integration`): workspace service suite and the signed job suite added; the isolation suite now includes the server-action IDOR registry.
- **Dependencies:** none new to the lockfile's package set (`inngest@4.22.0` and `zod@4.6.5` were already locked by Spike G / Spike C); only importer entries changed.

## 4. Security review

- **Authorization order.** Every command: workspace id (browser selector) → `resolveTenantScope` (membership) → `authorize()` → lookup → mutation + audit in one RLS transaction. A non-member gets `NOT_FOUND` for a foreign and for an unknown id alike; a member without the capability gets `FORBIDDEN` before any lookup, so the answer never depends on whether the target exists. Refusals are audited with `result = 'denied'`.
- **Defence in depth (SEC-10).** The database repeats the member-management rules: an editor's raw `UPDATE app.memberships` matches nothing; an admin's raw promotion to owner, removal of an owner, or owner INSERT raises 42501; a job scope (no actor) cannot write memberships; an admin cannot cancel a deletion even with raw SQL; an owner cannot back-date a purge.
- **Last owner.** Leave, remove and demote of the last owner fail with `LAST_OWNER`; concurrent mutual demotion of two owners leaves exactly one owner (5/5 rounds).
- **Invitations (SEC-11 style).** 256-bit token, SHA-256 at rest, 7-day expiry, revocable, single use under a 12-way race; accepted only by the account whose verified address equals the invited one; invalid, expired, revoked, used and "workspace not active" all answer `invalid`; the preview masks the address; the token never appears in a query string (an httpOnly cookie carries it across sign-in); `/invite/*` is `no-referrer` + `no-store`. Audit metadata never contains the address or token (asserted).
- **Jobs (ADR-007).** Payloads are ids only (sender and function both validate; a payload with an address is dead-lettered without retries); the serve route refuses unsigned calls (401); dev mode/inline/missing keys are refused on Vercel preview/production.
- **Privacy.** New data: invitee address and role (privacy inventory row added). Logs carry ids only (checked in the smoke log). The member directory exposes names/addresses only to members of the same workspace.
- **Abuse.** Workspace and invitation limits (D6). Server actions have no per-IP rate limit of their own yet; they require a verified session. Reviewed again in S9 (rate-limit review).
- **Residual.** `acceptInvitation` tells the token holder "wrong account" (a valid token addressed elsewhere): accepted, because holding the token is the credential. No outbox (D4). `/api/inngest` edge rate limit (G-6) open (DG-17). Threat model updated (six rows).

## 5. Schema, compatibility, migration and rollback

One forward-only migration; `schema.prisma` changed only in a doc comment (`db:drift`: no difference). Policies were replaced (`tenant_*` → `manager_*`) on `memberships`, `invitations` and `workspaces`; other tables untouched. The CHECK `workspaces_slug_not_reserved` fails the migration if a reserved slug already exists: live Supabase must be checked first (no product workspace is expected there). Rollback before product data exists: a reverse script (drop the triggers, definer functions and new policies, restore the S1 `tenant_*` policies, drop the two constraints, revoke the new `svc_definer` grants) was exercised locally many times during development (scratchpad `s5-down.sql`); after data exists, forward fixes only. New environment variables: `JOBS_TRANSPORT`, `INNGEST_DEV`, `INNGEST_BASE_URL` (local only); `INNGEST_EVENT_KEY` / `INNGEST_SIGNING_KEY` become required on Vercel (DG-17).
