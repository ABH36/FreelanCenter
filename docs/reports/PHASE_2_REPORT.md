## 1. What Phase 2 delivers

A visitor can open a site rendered from a validated SiteConfig, with no per-site build and no tenant JavaScript. A freelancer can pick one of three built-in templates, make a signed, expiring, login-free preview link in the dashboard, send it to a prospect, see their links, and turn one off.

## 3. Quality evidence

Harness: `tests/quality` runs the real `serveHost` from `apps/sites` over HTTP, one site per built-in template (English and Hindi), fonts from the sites app's own folder. Only the database lookup is a stub.

- **Accessibility (axe-core, WCAG 2.1 A and AA): 66 of 66 runs pass.** The home page of each template, and a gallery of **all 24 block variants on five backgrounds** (page, surface, primary, secondary, accent) under each template's theme, English and Hindi, mobile and desktop.
- **Behaviour axe cannot judge (per template, mobile and desktop):** reduced motion switches every animation off; forced colours keep buttons distinguishable; no horizontal scrolling at 320 CSS px (WCAG 1.4.10); keyboard only: skip link first, visible focus everywhere, no trap.
- **Cross-browser (Firefox, WebKit on an iPhone profile): 13 of 13.** The page renders, fits, loads its own fonts, breaks no CSP rule and passes axe; the collapsed menu works with the keyboard.
- **Lighthouse mobile (13.5, median of 3; simulated slow 4G, 4x CPU):** performance 97 to 100, accessibility 100 / 100 / 96, SEO 100, best practices 100; LCP 1.2 to 1.4 s, CLS 0 to 0.012. The 96 on wedding-royal is a measurement artefact of the scroll-driven entrance animation (text below the fold is partly transparent until it scrolls in); axe, which waits for the final state, passes. The robots.txt audit is skipped because Lighthouse fetches it through the page, where the strict CSP blocks it; robots.txt is asserted directly.
- **Visual regression: 12 baselines** (home page and gallery of the three templates, mobile and desktop), made and re-checked in the Linux Playwright image.
- **Dashboard (Playwright journey, real Chromium, real servers): 11 of 11,** including axe on 10 signed-in pages plus sign-in and sign-up.

## 5. Security review

- Tenant isolation: the template and link tables have RLS (FORCE); the isolation suite (232 tests, 13 of 13 mutations killed) and the IDOR harness cover the new tables, actions and page loaders.
- Preview links: signed, expiring (30 days at most), `noindex`, no-referrer; stored link rows hold no token and no prospect name; revocation is one way at the database; the sites app fails closed. Threat model rows were added in each slice.
- The renderer: allow-listed serializer, no tenant JavaScript, hash-based CSP, every href re-checked.
- No secret was printed or stored by any step; live changes were applied only with the Owner's approval (S5b migration and seed, S8b migration).
- Open: DG-27 (dashboard production is not configured), so none of the dashboard features can be used live yet.
