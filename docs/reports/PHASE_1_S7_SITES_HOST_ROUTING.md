## 2. What was built

- **Migration `20261026120000_p1_s7_host_routing`** (forward-only, additive): `app.resolve_host(text)` (SECURITY DEFINER, `search_path = ''`, owned by svc_definer, EXECUTE for app_public only); svc_definer gains SELECT on `projects.status` and `domains.status`. No table, column or app_user policy change.
- **`@platform/db/public`** (new subpath): `createPublicDatabase` (pg pool only, no Prisma; refuses any URL that is not app_public; per-query timeout 3 s; `verifyRole`). `db:verify` now has 24 checks (was 21): the definer list includes `resolve_host`, app_public executes exactly it, an unknown host resolves to `unknown`, app_public cannot allocate subdomains.
- **`@platform/providers`**: `KeyValueStore`, an Upstash REST adapter (no SDK; GET, SET EX, DEL; 1 s timeout; https required except for a local emulator; errors never contain the token, keys or values), a memory store for tests, `loadKeyValueConfig` (required on deployments, none locally, one of two variables is an error).
- **`@platform/hosting`** (new package): `normalizeHost`, `createHostResolver` (cache → lookup → write back; cache errors fall through; database errors are not cached; single-flight per host), `invalidateHosts`, `HOST_CACHE` (key prefix and TTLs), `LOCAL_UPSTASH` (tests).
- **`@platform/jobs`**: event `sites.hosts.changed.v1` (`{workspaceId, projectId}`), function `sites.host_cache.invalidate.v1` (5 retries, 5 per workspace, no idempotency key, dead-letter hook), emitter `siteHostsChanged(ids, { eventId })`, inline transport.
- **`@platform/workspaces`**: `createProject`, `duplicateProject` and `transitionProject` write a `sites.hosts.changed.v1` outbox row in their transaction and dispatch it after commit; `createHostCacheInvalidationHandler` (job scope: reloads the project's host names through RLS, soft-deleted ones included, and deletes their keys).
- **`apps/dashboard`**: wires the invalidation handler; the Upstash store is built on first use (D10).
- **`apps/sites`**: `app/[[...path]]/route.ts` (GET and HEAD; other methods 405), `lib/serve.ts`, `lib/pages.ts` (four static documents), `lib/runtime.ts` (app_public client + resolver, built lazily, role check, a failed start-up check is retried), `lib/security-headers.ts` used by `next.config.ts`. The Phase-0 scaffold page is removed.
- **Local stack and CI**: Redis 7.4 and serverless-redis-http (an Upstash REST emulator) added to `packages/db/docker/compose.yml`, both pinned by digest; CI step "Host routing cache suite".
- **ESLint**: apps/sites may import `@platform/db/public` but not `@platform/db`, `@platform/db/testing`, `@platform/workspaces`, `@platform/jobs` or Prisma; relative cross-app imports are now caught in both directions (S7-2).
- **Dependencies:** none added (two Docker images for local/CI only).

## 4. Security review

- **Visitor role (SRS 5.3 item 1).** app_public: no privilege on any product relation (catalog-checked for every relation, plus a denied SELECT on each); EXECUTE on exactly `app.resolve_host`. The function matches one exact, lower-cased host name (no LIKE, so `%` and `_` are literal), returns outcome + two ids, ignores `app.workspace_id`/`app.user_id`, and has a length guard. Mutations M8 (a column grant on `domains`) and M9 (EXECUTE on the allocator) are killed.
- **What a visitor learns.** Only which of four pages a host shows. The ids stay on the server (cache value and debug logs). An unknown host and a deleted or archived project look the same (404). A host name is public anyway (DNS).
- **Cache integrity.** Keys are per host and versioned; values are validated on read (shape, UUIDs) and otherwise treated as a miss; only apps/sites writes them, from `resolve_host`; the dashboard job only deletes. The Upstash token is a server-only variable in both projects. Staleness is bounded by the TTLs.
- **Abuse (SEC-09).** An invalid Host header gets 404 without any I/O; unknown hosts are negatively cached; concurrent misses share one lookup; the lookup has a 3 s timeout and a pool of 3; Vercel routes only attached domains. Per-IP rate limiting of public endpoints is the S9 review (no public write endpoint exists yet).
- **Pages.** No script, no tenant data, no host echo, no cookie; framing denied twice (CSP and XFO); `noindex` (preview hosts must be noindex: environment policy rule 7).
- **ADR-002.** apps/sites holds two credentials (app_public URL, Upstash token) and imports no dashboard code, auth, tenant client, services or jobs (lint, probed).
- **Privacy.** Upstash stores host names and internal ids only; the new event carries ids only. Privacy inventory: Upstash and Inngest rows updated; the Upstash region is still to be confirmed (DG-19).
- **Residual.** Until S8 emits invalidations, a suspension takes up to 300 s to show. A Redis outage means every request reaches the database (bounded by the pool and timeout). Threat model: four rows added.

## 5. Schema, compatibility, migration and rollback

One forward-only, additive migration (one function, two column grants); `schema.prisma` unchanged (`db:drift`: no difference). New event `sites.hosts.changed.v1` and function `sites.host_cache.invalidate.v1`: an Inngest resync is needed on the deployed dashboard (7 functions with failure handlers; S6: 5). New variables: apps/sites `DATABASE_URL_PUBLIC`, `DATABASE_SSL_ROOT_CERT`, `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN`; dashboard `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN` (DG-19). Rollback: `DROP FUNCTION app.resolve_host(text)` and revoke the two column grants (no data depends on them); outbox rows of the new event left undispatched by an older build fail with "unknown outbox event" in the sweep until the build returns, and can be marked dispatched by an operator.
